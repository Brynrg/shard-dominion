> glyph + color by WEAPON TYPE (so a player can tell an anti-vehicle rocket unit from an anti-infantry rifle unit
> at a glance), plus a team tint. No sim changes, no new components. Work in place. Edit ONLY `src/view/renderer.ts`

## Why
S4B's gate is "win a counter-based fight READ FROM SHAPE." The RPS logic already works (S4B-1); this makes the
roles visually legible: BULLET (anti-infantry) vs ROCKET (anti-vehicle) vs SHELL (anti-armor) must look different.

## What to do (skeleton — adapt to the existing `drawEntities`)
- Pass the loaded `weapons` into the view (add `weapons?: WeaponsFile` to `ViewConfig`, provide it from `main.ts`
  where `makeView({...})` is called — `weapons` is already loaded there for the combat systems).
- In the entity draw loop, for any entity with a `combat` component, choose its look from the weapon TYPE
  (`weapons.weapons[combat.weaponId]?.type`) instead of the default square:
```ts
// shape + fill by weapon type (role reads from shape):
//   BULLET  -> small filled CIRCLE      (anti-infantry)
//   ROCKET  -> upward TRIANGLE          (anti-vehicle)
//   SHELL   -> filled SQUARE w/ a bar   (anti-armor)
//   (default/no combat) -> keep the existing square
// team tint: player = cyan-ish stroke, enemy = red-ish stroke (outline the glyph so team is clear too).
const type = e.components.combat ? weapons?.weapons[e.components.combat.weaponId ?? '']?.type : undefined;
```
  Draw the glyph centered at the entity's interpolated `worldToScreen` position (same position math the current
  entity draw already uses — do NOT add inline pixel/tile math; reuse `worldToScreen`). Keep health bars (S4A-5)
  working on top.
- Keep it simple and legible at 1× zoom (glyphs ~0.7 tile). No sprite loading — pure canvas shapes.

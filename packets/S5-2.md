## The three states (per MASTER_PLAN §5.7)
- **visible** (tile key in `fog.visible`): draw the terrain in FULL color; draw entities normally.
- **explored** but not visible (in `explored`, not in `visible`): draw the terrain DIMMED (e.g. overlay ~55% black
  or multiply brightness ~0.45); do NOT draw live entities on it.
- **unexplored** (in neither): draw the tile near-BLACK (`#050505`); no entities.

## What to do (skeleton — adapt to the existing draw functions)
- Add `getFog?: () => { visible: Set<string>; explored: Set<string> }` to `ViewConfig`; provide it from `main.ts`
  where `makeView({...})` is called — pass the fog system's live sets (register a `makeFogSystem()` in the
  `orderSystems([...])` array too if it isn't already, and keep a ref for the accessor).
- In `drawTerrain`, compute the tile's state from `getFog?.()` and shade accordingly:
```ts
const fog = getFog?.();
const key = `${tx},${ty}`;
const isVisible = fog ? fog.visible.has(key) : true;
const isExplored = fog ? fog.explored.has(key) : true;
// pick fill: unexplored -> '#050505'; explored-not-visible -> dim the terrain color; visible -> full color.
```
- In `drawEntities`, skip an entity whose tile (`worldToTile(pos)`) is NOT in `fog.visible` (so enemies in fog are
  hidden; player units are always on visible tiles). Keep health bars/glyphs for the ones you do draw.
- Reuse `worldToTile`/`worldToScreen` — no inline pixel/tile math. If `getFog` is undefined (older callers), treat
  everything as visible (no regression to S0–S4 gates).

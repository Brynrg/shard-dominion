## Design (follows the existing intent architecture — do NOT invent new state homes)
- Two new intents in `src/view/input.ts`:
  `| { type: 'assign-group'; group: number }  | { type: 'recall-group'; group: number }`
- `onKeyDown` additions: keys `'1' | '2' | '3'` — with Ctrl/Meta held → `assign-group`, plain → `recall-group`.
  (Don't break the existing arrow-pan / D / B / Escape handling.)
- In `makeCommandSystem`, keep a closure map like the markers pattern:
  `const groups = new Map<number, EntityId[]>();`
  - `assign-group`: `groups.set(intent.group, state.store.all().filter(e => e.components.selection?.selected).map(e => e.id))`
  - `recall-group`: deselect ALL entities, then for each stored id still alive (`state.store.get(id)`), set
    `selection = { selected: true }`. Dead/removed ids are skipped (and may be pruned).
  Expose `groups` on the returned system object (like `markers`) for tests. Import `EntityId` type from ids.js.

## Required test — `tests/unit/controlGroups.test.ts` (like command.test.ts: queue + runTick + system ref)
- Select two units (set their `selection` directly), push `{type:'assign-group', group:1}`, tick → `groups.get(1)`
  has both ids.
- Deselect all (push `{type:'deselect'}`, tick), push `{type:'recall-group', group:1}`, tick → both selected again.
- Kill one grouped unit (remove it from the store), recall group 1 → only the survivor is selected; no crash.
- Recalling an empty/unassigned group deselects everything and selects nothing (no crash).

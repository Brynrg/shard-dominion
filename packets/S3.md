## Goal (the player-visible gate)
From the deployed base the player can: **deploy an MCV into a Construction Yard**, **queue a structure** at the
ConYard (credits drip down as it builds), then **place it** with a cursor preview that reads **VALID / INVALID
(with one exact reason)**; a valid placement spawns the structure. A structure built **on a concrete slab** is at
full HP; **off-slab** it spawns at reduced HP. A **Power Node** supplies power; a structure reads **POWERED** only
while base supply ≥ demand.

## Architecture rails (follow these — they're the AGENTS.md rules applied to S3)
- **Numbers from data, per-tick via `SIM_TICK_RATE`.** Build progress and credit drip are `perSecond / SIM_TICK_RATE`
  per tick. Costs/times/sizes/power all come from `data/structures.json` behind the new zod schema — no literals in
  systems.
- **Placement is world/tile space in the sim; screen only in the view.** The view converts the cursor pixel →
  TILE via `screenToTile` and queues a `place-structure` intent (tile + structureId). The `command`/construction
  path validates it against `state.grid` (buildable terrain? within build radius of a ConYard? enough credits?)
  and spawns the building — the sim never sees pixels.
- **Validation returns exactly ONE reason** (`INVALID TERRAIN` / `OUTSIDE BUILD RADIUS` / `BLOCKED` /
  `INSUFFICIENT CREDITS`); the view renders that one reason under the ghost.
- **Power is base-wide:** the `power` system sums supply and demand across the player's buildings and sets each
  `building.powered`. S3 = a boolean (supply ≥ demand). **Staged brownout bands are OUT — that's a later slice.**
- **Concrete = HP only for S3:** on-slab spawns at `onSlabHpFraction` (1.0), off-slab at `offSlabHpFraction`
  (~0.7). **HP decay over time, adjacency-to-qualifying-building, and repair are OUT — later slices.**
- Additive components only; register the new systems via `orderSystems` (SYSTEM_ORDER already has `construction`,
  `production`, `power` slots). Selection/move from S2 still work.
